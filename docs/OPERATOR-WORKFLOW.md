# 작업자 흐름과 독립 결과 스키마

## 작업 흐름

시작 화면과 주 메뉴를 자료 준비 → 객체 선택 → 연결 → 검증 → 검토·제출의 다섯 단계로 구성했다. 단계별 안내 화면에 해당 작업을 수행하는 버튼을 배치하고, 기존23개 도구를 하위 메뉴로 보존했다. 기존 data-tab 식별자와 API를 유지한다. 화면의 기존 기능 번호 대신 작업 단계/도구 이름을 표시한다.

| 단계 | 작업 |
|---|---|
| 자료 준비 | 설비·논리 연결, 엑셀/설정 파일 가져오기, PLC 소스, 상수·외부 값, 독립 결과 스키마, 기존 작성본 이전 |
| 객체 선택 | 공통 의미, 논리 구조·구조 배열, 객체 인스턴스, 템플릿 선택·사용처 |
| 연결 | 여러 소스 객체, 공통 입력 객체 배열, 직접 매핑, 값 그래프, 제한 수식, alias/view, 기존 레코드 전용 매핑 |
| 검증 | 저장한 객체/배열의 가상 입력 검증, 개별 값/그래프 진단, 메모리맵 의미 비교, 독립 정답·현장 평가 준비 |
| 검토·제출 | 변경 비교·검토 기록, 의미 URI 관리, 템플릿 영향 조회, Bifrost 제출·승인·릴리스 상태 |

설비·객체 의미 모델·결과 스키마·템플릿의 선택은 같은 origin의 sessionStorage에 보존하고 연결 화면에서 이어받는다. 선택은 저장된 정의의 자동 변경이 아니다. 자동으로 이어받은 선택만으로 미저장 경고를 만들지 않는다. 직접 작성한 입력이 있으면 다음 단계 이동을 막고 검증·저장을 안내해 입력을 보존한다. 기존 하위 메뉴로의 이동/되돌아가기는 기존 미저장 확인 동작을 유지한다. 검증에서 객체/배열을 열면 가상 입력 영역으로 이동하고, 검토에서 템플릿 영향을 열면 검토 단계 문맥을 유지한다.

객체 선택에서 설비와 의미 모델 또는 템플릿을 선택한다. 연결에서는 단일 객체/레코드별 객체 배열/상세 매핑 도구를 고른다. 연결 정의를 검증·저장한 뒤 가상 입력을 검증한다. 검증 결과는 실제 취득이나 현장 정답 인증이 아니다. 제출 후 서명 승인·발행은 별도 Bifrost 권한 경계에 남긴다.

## 독립 결과 스키마

새 `자료 준비 → 결과 스키마` 화면은 매핑·템플릿을 생성하지 않고 다음을 저장한다.

- 스키마 ID/버전·표시 이름·providerRef/valueKey와 쿼리 원문 메타데이터
- 필드 ID/이름·String/Boolean/Int32/Double·단위·raw/already-engineered·nullable
- NULL을 허용하지 않는 필수 String 식별 키1~4개, 미정의 필드 보존/거부
- 작성자·작성/개정 사유·근거 메모·작성 시각, 선행 버전의 canonical SHA

필드 표로 작성하고 검증→확인한 스키마 저장 순서로 진행한다. 기존 스키마의 초안을 복사해 새 버전을 작성할 수 있다. 저장된 버전과 사용 중인 매핑 ID/이름/버전을 함께 표시한다. 스키마 개정은 기존 매핑을 자동 변경하지 않는다. 다른 필드/단위/키는 새 스키마 버전과 새 매핑 버전에서 명시적으로 사용한다.

객체 배열 연결은 독립 카탈로그의 스키마를 직접 선택한다. 기존 레코드 전용 매핑에 포함된 inline 스키마도 계속 선택할 수 있다. 따라서 기존20 경로를 먼저 저장할 필요가 없다. 새 스키마 ID/버전은 같은ID/버전의 기존 inline 스키마와 내용이 충돌할 수 없다.

## 편집 계약·SQLite·발행 경계

`editor-contracts/1.0.0/result-schema-definition.schema.json`은 편집용 계약이다. wrapper는 kind=result-schema-definition/schemaVersion1.0.0, id/version/label/resultSchema/previousSchemaRef/author/provenance를 가진다. resultSchema 본문은 기존 wire2.20/2.22의 형식을 그대로 사용한다. wrapper id/version과 본문 id/version이 같아야 한다. 최대256개 정의, ID별32개 버전, 불변 선형 선행 SHA를 검증한다.

workspaceVersion2.0.0의 선택 배열 resultSchemas를 추가했다. 기존 SQLite workspace JSON/CAS를 사용하며 새 테이블·자동 DDL·마이그레이션은 없다. 기존 workspace에 키를 자동 삽입하지 않는다. 읽기·목록 조회는 DB를 바꾸지 않는다. 과거 정의 수정/삭제, ID/버전 중복·선행 SHA 오류·키/타입/필드 오류·동일 버전 inline 충돌을 거부한다. plan은 읽기 전용이고 apply는 plan hash와 workspace revision을 재검사한다.

- GET /api/result-schemas: 독립 카탈로그 + 기존 inline 스키마, 본문 pin/편집 정의 pin/사용처.
- POST /api/result-schema-plan: 저장할 definition과 revision을 검증하고 planSha256 반환.
- POST /api/result-schema-apply: 같은 definition/planSha256/revision으로 원자 저장.
- 기존 /api/record-compose, /api/broadcast-compose, /api/record-apply 등 요청 형식은 유지한다.

사용된 스키마는 매핑의 기존 resultSchema 본문으로 고정된다. Bifrost에는 기존2.22 recipe·템플릿·의미·소스·근거 closure를 제출한다. 편집 카탈로그 wrapper나 사용되지 않은 스키마, 가상 입력은 발행하지 않는다. Bifrost 코드·wire 계약·JAR를 변경하지 않는다. 카탈로그 편집 메타데이터의 별도 거버넌스 발행은 이번 범위에 포함하지 않는다. 앱 간 공용 코드나 Java→Python 호출을 추가하지 않았다.

## 기존 기능과 제한

기존22의 독립 스키마 선택을 추가하면서 기존20의 스키마 선택 alias도 보존한다.21의 단일 레코드 필드 소스는 기존 recordMappingRef 계약을 그대로 사용한다. 모든 기존 수동/고급 편집 도구는 하위 메뉴에서 계속 접근할 수 있다. 본 개편은 운영 런타임·커넥터·SQL 실행·장치 쓰기를 추가하지 않는다.

실제 작업자 관찰과 작성/검토 시간, 잘못된 선택률, 실제 현장 문서와 provider export, 키/NULL/단위 정답은 별도 현장 PoV다. 합성 브라우저 성공으로 작업자 사용성을 인증하지 않는다.


## 작업자 화면 직접 검증 후 보완 (2026-10-20)

검증 단계의 객체 배열 화면은 저장된 프로퍼티·소스·변환·스키마/템플릿 버전을 먼저 요약한다. 신규 작성 폼은 기본 접고 필요하면 펼친다. 연결 단계에서는 원래 작성 도구와 고정 템플릿 재사용을 유지한다. 입력 선택 옆에 행별/공통 적용 범위, 입력 타입·단위·원시/공학 단계와 출력(재사용 시 슬롯 요구 타입)을 표시한다. 문자열의 숫자 변환과 해당하지 않는 NULL 설정은 비활성화한다. 같은 모델/템플릿 문맥에서 후보가 유효한 연결과 변환은 선택 재확인 시 보존한다. 다른 후보·모델의 의미를 자동 추정하지 않는다.

가상 DB 행을 표에서 추가·제거하고 키/필드를 직접 입력할 수 있다. 기존 JSON 편집과 미정의 열 보존을 유지한다. 가상 입력이 바뀌면 이전 미리보기 결과를 지우고 재검증을 안내한다. 중복 키·bad 품질은 원래 코드와 함께 한국어 해결 안내를 표시한다. 같은 revision/매핑의 화면 간 이동에는 입력 초안을 메모리에서 보존하며, 새로고침 후 복구는 기존 SQLite 가상 시나리오 저장을 사용한다. 메모리 초안은 승인 근거나 영구 저장을 대신하지 않는다.

검토·제출에는 방금 다룬 배열 ID/버전·소스/변환 요약과 세션 내 미리보기 상태를 표시하고, 제출 화면에서 그 배열을 미리 선택한다. 사용자가 선택을 바꾸거나 다른 매핑을 추가할 수 있다. 기존 담당자 검토 기록의 대상 범위를 배열 승인으로 확대하지 않는다. Bifrost 검증·서명 승인 권한은 그대로다. 작업 중에는 처리 중 표시를 제공한다.

[직접 검증 기록](verification/OPERATOR-UX-WALKTHROUGH-RESULTS.md).


## 빈 작업본·엑셀에서 시작 (2026-10-20)

빈 작업본은 자료 준비의 시작 안내에서 기존 백업/CAS 이전 경로를 명시적으로 실행한다. 설비와 PLC 논리 연결을 등록한 뒤 엑셀을 가져온다. 사용자 열 이름을 표준 항목에 대응하는 표의 제안을 확인하고 적용·재해석한다. 고급 JSON과 원본/미해석 열 보존을 유지한다. 채택한 소스는 검토할 초안 목록에서 근거·주소·타입·폭·단위를 확인하고 정의 완료로 저장한다.

공통 의미에서는 객체의 프로퍼티를 저장한 뒤 같은 객체에 다음 프로퍼티를 연속 추가한다. 독립 결과 스키마를 준비하고 객체 선택에서 설비/모델을 고르면 연결 화면으로 이어진다. 표현식이 없는 외부 값은 빈 원문 입력을 요구하지 않는다. 초기 작업본 조회가 완료되기 전에는 메뉴를 비활성화한다. 기존 계약·SQLite DDL·Bifrost 권한 경계를 유지한다.
