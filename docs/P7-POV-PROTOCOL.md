# 현장 PoV 인수·독립 평가 절차 — 실제 수행 미완료

이번 단계에서 준비한 것은 절차와 실행 도구다. 실제 자료·독립 정답·측정이 없으므로 현장 PoV를 완료로 기록하지 않는다.

1. 자료 제공 담당자가 파일 전달 권한과 평가 범위를 정한다. [인수 양식](templates/p7-intake-template.json)에 제품/버전·동시점 문서와 설정/개정본·파일 SHA·가명화 대응표 관리자를 기록한다. 가명화 대응표는 평가 pack과 분리해서 담당자가 보관한다. 사이트/설비/사람 이름, IP·계정·접속 문자열·비밀값을 점검하며 도구가 자동 익명화/비밀 제거를 수행한다고 가정하지 않는다. 주소/offset/stride·심볼 계층의 비교 관계를 훼손하면 그 부분은 평가 불가로 기록한다.
2. 조정용·평가용·튜닝에 사용하지 않은 별도 설비를 파일/업무 단위로 먼저 나눈다. 같은 원본을 이름만 바꿔 heldout에 넣지 않는다. 원본 hash와 split 대응을 동결하고 평가용 자료를 보고 parser/profile을 바꾸면 새 실험으로 분리한다.
3. 도구 개발·튜닝에 참여하지 않은 담당자가 50~100개 기준 항목을 독립 작성한다. 소스 접근/타입/단위/변환·객체/멤버/의미·근거를 확인하고, 값·결측·bad 품질·스케일/단위·손실 사례의 정답을 도구 출력과 별도로 만든다. 현재 inventory pin을 단순 복사한 경우 독립 검토로 계산하지 않는다. 불일치는 근거와 합의 기록을 남긴다.
4. manual/tool에서 동일한 작업 범위를 사용하고 참가자/작업별 수행 순서를 교차한다. 파일 준비·해석·매핑·문의·오탐 수정·재검토 시간을 여섯 단계로 기록한다. 타이머/원시 작업 기록은 인수 자료와 함께 보관하고 평가 pack에는 가명 participant/task와 단계 합계를 넣는다. 미완료·중단·추가 문의 시간을 숨기지 않는다.
5. 정답 pack을 동결하고 별도 담당자가 현재 저장본에 대해 CLI 또는 16 화면의 읽기 전용 평가를 실행한다. pack/report/workspace hash와 revision, 실제 원본 파일 SHA, 실행 버전과 검토 선언을 함께 보관한다. 도구의 report pin은 디지털 서명이나 외부 anchor가 아니다.
6. split별 기준 항목 수와 missing/ambiguous/unreviewed/의미 불일치/정의 차이/샘플 오류/손실 진단·추가 미평가·전체 시간·수동 보정량을 검토한다. 정의 차이는 원문과 비교해 원인/의미 영향을 분류한다. 정확도와 검토 시간은 같은 범위와 분모로 제시하고 중요 정보의 조용한 누락이 있으면 원인을 해결하기 전 확대하지 않는다.
7. 계획의 정밀도 95%·전체 시간 30% 단축은 목표이며 이번 합성 결과의 실적이나 자동 승인 기준이 아니다. 현장별 오매핑 허용치·누락 처리·책임자를 평가 전에 합의한다. 별도 설비 재사용성과 의미 확인 책임, 익명화로 검증 불가한 항목을 함께 기록한다.

장치 접속·live browse·외부 SQL·쓰기 실행·운영 활성화는 평가 절차에 포함하지 않는다. 운영 IAM/bootstrap·전원 손실 durability·목표 Windows 배포/전체 방화벽·vendor native layout 수용은 별도 책임/환경 검증이다. field-declared 업로드나 독립성 체크만으로 현장 인증이 되지 않는다.
