2026-10-20. CUA 브라우저에서 실제 버튼·선택·필드 입력으로 진행했다. 사용자 기존 DB를 변경하지 않고 합성 workspace에서 시작한 별도 작업본을 사용했다. API 직접 호출이나 레코드 전용20 작성으로 화면 경로를 우회하지 않았다.

## 수행 경로

초기에는 설비·PLC/상수/외부 소스와 공통 의미만 있고 레코드 매핑/템플릿은 없었다. 자료 준비에서 record_id String 키와 target Double/kPa 원시 필드의 독립 결과 스키마를 직접 저장했다. 객체 선택에서 설비B·5프로퍼티 모델을 선택하고 연결 단계에서 PLC actual, DB target, 상수 baseline/line_code, 외부 reference를 연결했다. actual/target 스케일0.1과 나머지 cast 정책으로 정의·템플릿을 원자 저장했다.

검증 단계에서 JSON을 편집하지 않고 행3개를 추가하고 마지막 행을 제거했다. PUMP-1/PUMP-2의 target900/950, PLC HEX b004, 외부101을 입력했다. 출력은 actual120/target90·95/baseline100/external101/line_codeLINE-A의 객체2개다. 중복 키와 공통 bad 품질은 전체 차단됐다. 키·품질 수정 후 다시 미리봤다. 목표960을 입력한 뒤 검토 단계에 다녀와서960이 유지됨을 확인하고950으로 복구했다. operator-ux-final 시나리오를 별도 SQLite에 저장했다.

새로고침 후 SQLite 시나리오의 PLC HEX b004·목표950을 복원했다. 기존 배열B가 있는 상태에서 새 작업 설비A를 선택해도 연결 작성 설비A가 유지됨을 확인했다. 최종 검토·제출에서 배열이 자동 선택됐고 ux-after 제출본을 저장했다. 기존 Bifrost 재검증 accepted=true/findings=[]와 승인 대기 상태를 확인했다. 서명 승인·발행은 수행하지 않았다. 브라우저 콘솔 오류는 없었다.
