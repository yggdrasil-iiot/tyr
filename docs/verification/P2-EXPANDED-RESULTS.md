## 자동 시험

[계약 회귀 결과·fixture/계약 해시](p1-expanded-regression.json)

검증 뒤 실제 저장 파일의 해시를 다시 대조했다. 24개 수용 시험에는 기존 저장·revision·API 검증과 다음 객체 사례가 포함된다.

- 네 PLC × 8개 신호, 8개 프로퍼티와 4개 객체 매핑의 전체 패키지 검증.
- D1000/D2000/D3000이 각 1워드로 별도 프로퍼티를 채우는지 확인.
- 다른 현장 이름이 같은 의미로 연결되고 PV/Status의 서로 다른 의미를 구분.
- 잘못된 단위 변환 쌍·시작 단위·끝 단위 및 변환 누락 검출.
- 1.0.0에서 새 단위를 조용히 허용하지 않는 호환 경계.
- 부분 객체의 빠진 프로퍼티 표시.
- 프로퍼티 편집 시 다른 프로퍼티·매핑 유지 및 SQLite 재열기.
- 실제 정의에서 읽은 바이트/typed 값·스케일·단위 변환·enum으로 독립 기준값 12개 평가.

표본 값은 2400 rpm 수렴, 125 N.m, 65 Cel, 서로 다른 상태 코드의 running 수렴과 알람 불리언이다. 일반 UI preview나 실측값 검증은 아니다.

## 화면 직접 검증

기본 확장 DB에서 다음을 확인했다.

1. 05 비교 화면의 객체×설비 주소 행렬과 신호별 32개 행.
2. PV 검색 시 실제 속도/토크의 의미 ID 차이와 ‘같은 이름·다른 의미’ 표시.
3. MELSEC 객체 매핑에서 8개 프로퍼티와 D1000/D2000/D3000의 독립 주소, 상태 enum, 0.1 계수.
4. MELSEC/OPC UA 객체를 저장하고 차단 항목이 없는 결과.
5. 새 서버 프로세스에서 샘플 DB revision 4와 32개 소스·8개 프로퍼티 복원.

별도 UI 시험 DB에서는 화면만으로 composed-motor 객체를 만들고 actual-speed, target-speed, state를 차례로 추가했다. MELSEC 세 소스를 골라 linear/enum을 작성하고 composed-melsec을 저장했다. 페이지 재열기 후 3개 행을 확인했고 DB 재조회에서도 세 프로퍼티·세 연결과 정상 검증 결과를 확인했다. 시험 데이터는 기본 샘플 DB에 섞지 않았다.

[최종 객체 주소 화면](object-memory-map.png)을 저장했다. 좁은 화면에서는 설비 필터로 하나의 객체를 확인하고 넓은 비교표는 가로 스크롤로 사용할 수 있다.

## 범위와 보존

객체 프로퍼티에 서로 다른 주소를 연결하는 구성을 구현했다. 여러 입력으로 하나의 스칼라를 계산하는 연산 그래프, 일반 값 preview, 실측·실장치 통신, Bifrost 실제 승인은 후속이다.

1.0.0 계약과 원래 workspace.sqlite3을 보존했다. 1.1.0 단위/연산과 확장 샘플은 별도 파일·DB에 기록했다. 초기 P2 결과는 역사 기록이며 이 문서가 최신 기능·검증 기준이다.
